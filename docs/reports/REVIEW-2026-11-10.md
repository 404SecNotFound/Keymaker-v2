## 2. Fix next (P1, open)

1. **"Random" then "Encrypt" seals behind a password the owner never saw.** Reviewer-confirmed in Chromium. `use-encryptor-state.ts:1835-1892` fills the masked field and toasts only the bit count. The password is cleared on success and the receipt does not mention it. This is the only open finding that can leave someone locked out of a good backup. Fix shape is a UI decision (see UI-DIRECTIONS-2026-11-10.md).
2. **Accepting an update in one tab reloads every other tab.** Reviewer-confirmed. `layout.tsx:190-195` reloads on `controllerchange` with no guard. A tab showing one-time shares or an unsaved text backup loses them. Fix. Defer the reload while shares, an unexported backup or a running job exist, and add a `beforeunload` prompt. **Partly fixed on this branch.** The other tab is no longer reloaded while it holds any of the three. Only the shares case has a test. The `beforeunload` prompt is not added.
3. **No visible focus indicator on text fields** (October 1.4). Trace. `ui/input.tsx:11`, `globals.css:454`, and `focus-visible:ring-0` at four call sites. **Fixed on this branch** with one stylesheet rule and a browser test.

## 6. Changes that would most improve the system

Ranked. [Inference] on the ranking itself.

1. **Make password custody a step.** Show a generated secret when it is made and hold Encrypt until it is copied, revealed or retyped. Closes the one finding that locks an owner out.
2. **Make a finished backup hard to lose.** Keep sealed bytes re-downloadable until wipe. Guard reload, close and update while shares or an unsaved backup exist. Say "download requested".
3. **Serve release bytes on the live site (Bet 1), with a `main` ruleset and a Dependabot cooldown.** Today a merged dependency bump reaches users in minutes and the release attestation never covers what they run.
4. **One front door in the recovery kit.** Act on `detect()`, refuse non-containers by name before any prompt, and give memory, EOF and encoding failures their own messages. Then "decryption failed" means password, key file or damage, in both languages.
5. **Make every freeze structural.** Fixtures are now pinned. Do the same for the vector pack, and add a CI step that fails when a pinned file or pin line is modified or deleted.
6. **Make negative tests assert the reason.** Typed error codes, visible error text, and no presence-conditional skips on Chromium.
7. **Run the page's decryptor in Node conformance.** It is the one reader `tsc` never sees.
